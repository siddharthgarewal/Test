Focused developer

.github/agents/focused-developer.agent.md
---
name: Focused Developer
description: Implements a scoped change with regression tests.
---
You are a focused development assistant.

- Start with the user's supplied files and acceptance criteria.
- Inspect dependencies only when needed.
- Make the smallest appropriate change.
- Add or update regression tests.
- Run relevant validation when available.
- Do not refactor unrelated code or add dependencies without approval.
- Ask before editing if requirements are unclear.
- Stop when the requested task is complete.

Report changes, actual validation, and remaining blockers.
Never claim tests passed unless they ran successfully.
Configure editing and validation tools in your IDE; rehearse permissions before presenting.

Focused reviewer

.github/agents/reviewer.agent.md
---
name: Focused Reviewer
description: Reviews supplied code for correctness and missing tests.
tools: ["read", "search"]
---
Review the supplied files and changes.

Focus on:
- Incorrect behavior
- Missing edge-case tests
- Compatibility risks
- Security-sensitive changes

Do not edit files. Avoid unrelated style suggestions.

For each finding, provide the location, problem,
impact, and suggested correction.
If no findings exist, state remaining validation gaps.

Shared rules

.github/copilot-instructions.md
# Project guidance

- Follow existing project conventions.
- Prefer minimal, task-focused changes.
- Preserve public APIs unless the task requires a change.
- Do not introduce dependencies without approval.
- Add tests for changed behavior.
- Never include credentials or secrets.
- Report what was actually verified.

Efficient task design

Broad exploration vs focused work

Broad baseline

Explore this project, fix the page-size bug,
improve the code, add tests, and explain everything
you changed.

Discussion: what does “improve” mean? Where should exploration stop? Which changes are in scope?

Focused alternative

Work on the attached validation function and tests.

Accept positive integer page sizes. Reject blank,
non-numeric, fractional, zero, and negative input.

Preserve the public result shape. No new dependencies.
Inspect other files only when needed for compatibility.
Add regression tests and run relevant validation.
Stop after this task; summarize changes and validation.

Discussion: relevant context, observable behavior, bounded changes, and an explicit completion condition.

Reusable prompt file

.github/prompts/fix-bug.prompt.md
---
description: Fix a scoped bug with regression tests.
agent: agent
---
Fix the bug described by the user.

- Identify expected behavior and relevant files.
- Ask if acceptance criteria are unclear.
- Reproduce the failure where practical.
- Make a minimal fix and add regression tests.
- Run relevant validation.
- Avoid unrelated changes.

Finish with changes, actual validation, and remaining risks.
Invocation and format: VS Code prompt files.

Context efficiency & usage worksheet

Data completeness: All usage measurements are missing until you enter observed values. No estimates, automatic token counts, percentages, or cost calculations are provided. Text length is not presented as token usage.

Recommendations to evaluate

  • Attach relevant implementation and test files.
  • Keep shared instructions concise; scope specialist rules.
  • Avoid irrelevant logs and unrelated exploration.
  • Request a concise final summary rather than full-file repetition.
  • Use a fresh chat for unrelated work, carrying essential context forward.
  • Restrict tools to what the role needs.
  • Set a clear stopping point and verify the outcome.
These are workflow recommendations, not guaranteed savings.

Fair comparison procedure

  1. Restore the same repository state.
  2. Use the same model and a fresh chat for each run.
  3. Run broad and focused workflows separately.
  4. Observe the entire task, including tool activity.
  5. Verify correctness and regression results.
  6. Record only usage fields actually exposed.

Inspect requests and diagnostics with VS Code troubleshooting / Chat Debug View. Verify the interface and fields in your installed version.
